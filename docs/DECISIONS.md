# Decisions

Short log of choices made where the brief was ambiguous or reality forced a deviation.

1. **Offline `fake` LLM mode (added to live/record/replay).** No OpenAI key was available while
   building, so `data/fixtures/llm_cache` could not be populated. `LLM_MODE=fake` runs deterministic
   heuristics (keyword extraction/classification, a shared task-template library, hash-based
   embeddings) through the same gateway and pipeline, and is the default in `.env.example`. `replay`
   still raises a clear error on cache misses as specified. Run `make warm-cache` with a key to create
   real fixtures.
2. **Embeddings in fake mode** are 1536-d feature-hashing vectors. Do not mix modes in one database:
   similarities between hash and OpenAI vectors are meaningless (reset + reseed after switching).
3. **Calibrate raw first, then blend with analogs** (§7.3): `raw_mid·exp(μ_pred)` is blended with
   `analog_mid` in log space. Analog hours already include history, so calibrating the blend would
   double count.
4. **Actual-layer scope**: `μ_a`, `n_a` come from the category's actual stats, falling back to global
   actual stats when a category has none; predictive variance combines layers with the same `k_a`
   weighting as the mean; σ² floored at 0.01.
5. **Shared project factor pool** = per-project mean of `(x − category shrunk mean)` from the actual
   layer, stored as `calibration_stats(scope_type='project', scope_key='shared')` (scope type added).
6. **Task removal vs. disable**: `DELETE /tasks/{id}` soft-removes (`removed=true`, `task_removed`);
   the enabled switch logs `task_toggled`. Both exclude the task from learning; removed AI tasks count
   as false positives.
7. **Reasons after the fact** (`POST /tasks/{id}/reason`) append a new `hours_changed` event with
   `field='reason'` instead of mutating the original event (append-only is enforced by a DB trigger).
8. **Rejected agent ops** are logged as `proposal_op_rejected` events (event type added).
9. **Estimate versions**: finalizing never un-finalizes older versions; the latest finalized version is
   "the quoted one" and the only one used for learning. Clones copy AI baselines so learning stays
   anchored to the raw output (for cloned tasks the first edit's `old_value` is the cloned value).
10. **Clarifying-question deltas** use the generated estimate's per-category applied factor so the
    displayed "±X h" is on the same scale as the calibrated estimate.
11. **Learning curve** uses a fixed test set per random ordering (last ⌊N/3⌋ ≤ 4 projects) and grows the
    training set from the rest, so the curve isolates the effect of more data.
12. **Backtest P80** = upper P80 quantile (coverage = share of actuals ≤ P80). Project level uses the
    same Monte Carlo as the app (shared factor only for calibrated estimators E3/E4). Interval width =
    (P90−P10)/P50.
13. **Synthetic realism**: the simulated raw LLM sees only `size^0.5` of project scale and has σ=0.25
    per-task noise. In an earlier version where raw estimates fully encoded size, analog blending hurt
    task-level accuracy (analogs carry other projects' sizes). With the spec's defaults
    (`w_per_analog=0.12`, `w_max=0.6`) analogs should be tuned per data set via the backtest.
14. **Result honesty**: on the seeded synthetic data E4 wins on project MdAPE, bias and P80 coverage,
    but at task level E3 (edit calibration) has slightly lower MdAPE than E4. Reported as is.
15. **Migrations**: the baseline Alembic revision creates the schema from the SQLAlchemy metadata
    (plus the vector extension and immutability triggers); later changes should be autogenerated
    revisions.
16. **Enums** are `VARCHAR + CHECK` constraints (easier to evolve than Postgres enums).
17. **Mendeley dataset**: download/licence unverified (HTTP 503 at build time); adapter maps columns by
    pattern and stops if ambiguous. Planning Poker → final range PP±15%.
18. **Routers**: documents/tasks/questions/jobs/health endpoints are grouped in fewer router modules
    (`projects`, `estimates`, `agent`, `actuals`, `insights`, `settings`) — same API surface.
19. **TanStack Table v9** (`useTable`) is used for the projects table; sorting/search are computed in a
    memo before handing data to the table (core features only). The estimate tree is a custom table
    because rows are grouped/drag-sortable.
20. **Next.js 16**: `cacheComponents` was disabled (client-side app; prerendering client hooks failed);
    Google fonts removed so Docker builds work offline.
21. **Demo auth**: `X-User-Id` from the user switcher (stored in `localStorage` as a UI preference);
    unknown ids fall back to the first PM.
22. ~~Placeholder prices~~ → superseded by 23.

## Live-model validation session (2026-10-18)

23. **Prices** live in `app/llm/budget.py::PRICES` (standard tier, verified on the pricing page today) with an
    `LLM_PRICES_JSON` override. Unknown models raise `UnknownPrice` instead of costing $0.
24. **Budget source of truth** = append-only file ledger `data/llm_spend.jsonl` (gitignored). The DB table
    `llm_calls` is wiped by `docker compose down -v`, so a DB-only cap could be reset by accident. Cache hits and
    fake calls cost $0 and are not written to the ledger.
25. **Section budgets nest**; every active section and the global cap are checked before each live call,
    including each model turn inside the LangChain agent (callback handler).
26. **Reasoning**: `reasoning_effort=none` for Luna (it supports `none`); temperature is only sent when
    reasoning is off/none. `model_key = model|estimation prompt version|r=<effort>`; fake mode is `fake-v1`.
27. **model_key partitioning**: estimates, baselines and raw estimates carry `model_key`. Calibration, analog
    retrieval and backtests use only the active key. On startup, stats are recomputed when the active key
    changes, and the UI shows a "calibration restarted" banner if the active key has no history.
28. **Bake-off stopped at A**: Luna passed every heuristic threshold, so Sol was not run (hard rule "move up
    only on failure"). The bake-off briefs are short synthetic briefs; the evaluation is small.
29. **Live seeding** re-estimates synthetic tasks with the live model (raw-estimation step only, K=3 per
    project, fixed task list) and keeps the simulated actuals. Simulated PM edits are re-expressed as the
    planted ratio applied to the live raw estimate. Category classification is not re-run (synthetic tasks
    already have categories).
30. **Agent cassettes**: live agent turns are recorded once (`scripts/record_agent_cassettes.py`) against a
    deterministic fake-mode estimate; tests replay them with a fake chat model, remapping task ids by title.
    In `LLM_MODE=replay` the API replays a cassette when the prompt matches, otherwise it uses the offline
    parser (badged "Offline demo agent").
31. **Agent prompt v2** (written before the bake-off, not tuned on it): document text is data, vague requests
    get a clarifying question or one bounded change, plus explicit tool-routing hints. A `propose_remove_module`
    tool was added; split proposals are rescaled to preserve the original min/max totals; no-op updates are
    refused.
32. **Backtest**: defaults kept and reported as is; no tuning on the evaluated projects. Ablations A1
    (edit-only, no analogs) and A2 (full without analogs) were added. Synthetic and dataset projects are never
    pooled (`data_source` filter, synthetic by default).
33. **Reorder**: keyboard drag (dnd-kit KeyboardSensor) was added. E2E uses it because pointer-drag was
    unreliable in headless runs.
34. **Agent operations**: every agent write is one `agent_operations` row (a list of primitive ops) applied
    atomically in a SAVEPOINT via `services/estimates.py`, so `edit_events` carry `operation_id`/`batch_id`/
    `session_id`. Undo appends inverse events (log rows are never edited); tasks the user changed after the op
    (detected by `tasks.row_version`) are skipped, giving a partial undo that is reported to the user.
35. **Migration 0003** is idempotent (`create_all(checkfirst)` + `ADD COLUMN IF NOT EXISTS`) because 0001 builds
    the schema from current metadata.
36. **Project retrieval keeps the learning partition**: `model_key` is NOT suffixed with `|ctx_k3`/`|noctx`,
    because that would orphan every existing edit/actual record from calibration. The variant is stored
    instead in `estimates.model_snapshot.retrieval.variant` and `task_ai_baselines.retrieval` so backtests
    and reports can split by it.
37. **Project cards are deterministic** (latest final estimate, edits vs AI baseline, actuals) and embedded
    per `embedding_model|card-v1`, re-embedded only when the card hash changes. Score = cosine + 0.05·tag
    Jaccard + 0.03 same domain + 0.05·category-share overlap (when known) + delivered boost; the
    min-similarity threshold applies to raw cosine, then MMR (λ=0.7) over the top 10. Fewer than k is
    returned rather than padding.
38. **References are appended to the decomposition/estimation prompts only when non-empty**, so prompts
    without references are byte-identical to before and existing replay fixtures still hit. In replay mode a
    cache miss on a context prompt (or on a new card embedding) degrades to `noctx` and records the reason,
    instead of failing offline demos.
39. **Agent confirmation is turn-based**: a write that needs confirmation is stored as an
    `awaiting_confirmation` operation, the run ends with `run_done{status: awaiting_confirmation}`, and the
    confirm endpoint applies it later. No server-side waiting or resumable graph state is needed, and a reload
    never loses a pending confirmation.
40. **fit_to_budget floor**: a fitted task keeps at least 25% of its current max (min 0.5 h). Cutting deeper is a
    scope decision, so the tool reports the feasible minimum and asks instead of squeezing tasks to 0.5 h.
    Budget fitting targets the sum of **max** hours (the number a fixed-bid quote must stay under).
41. **Split and merge are not "deletes"** for the always-confirm rule (hours are preserved); `delete_tasks` is.
42. **Rolling summary is extractive (deterministic, free)**, not LLM-written: reproducible, no extra spend,
    and it cannot inject instructions. Project memories are labelled with their origin; origin=document is
    presented to the model as data only.
43. **Slash commands bypass the LLM** in every mode and go through the deterministic planner, which also
    serves fake/replay mode, so the offline demo exercises the same tools, policy and events as live mode.
    The legacy proposal-based `/agent/messages` endpoint stays for the current UI until Phase 5 replaces it.
44. **Agent panel UI**: the timeline is rebuilt from persisted messages + operations after every run (live
    SSE items are only shown while streaming), so reload/reconnect shows the same cards, and Undo/Confirm
    buttons always reflect the operation's current status. One session per estimate is auto-created, titled
    after the uploaded files; the panel auto-opens after generation and toggles with Ctrl/⌘+J. The legacy
    proposal card remains only for "answer a clarifying question" in the Questions tab.
45. **Accounts**: server-side sessions (opaque token, HMAC-SHA256 digest stored, 7-day sliding expiry) in an HTTP-only
    `SameSite=Lax` cookie; argon2id passwords (min 10 chars); double-submit CSRF (`calibr_csrf` cookie echoed as
    `X-CSRF-Token`) enforced by middleware on every non-GET `/api/*` call; login throttling (5 failures / 15 min per
    IP+email, exponential backoff) with one generic error message. The API is reached through Next.js rewrites so all
    cookies are first-party (no cross-site cookies, CORS only for local tools).
46. **Authorization is central**: one router-level guard resolves every id in the path (project, estimate, task,
    module, document, session, operation, batch, memory, proposal, question, unplanned, job, backtest run, rule) to its
    project/owner and checks access — 404 when invisible (no id probing), 403 for viewer writes. List endpoints
    filter by visibility. Cross-user tests in `backend/tests/test_authz.py`.
47. **Archive ownership**: pre-account projects are flagged `is_archive` by migration 0004 and assigned to the first
    admin at startup (idempotent backfill of rows without an owner). Pre-account users are kept as archived, inactive
    accounts (no password) so edit-log foreign keys stay valid.
48. **Learning pools**: admin = everything (stored calibration tables). Members: own + shared-with-me +
    `shared_to_workspace` projects (+ the archive only if the admin switch is on); their calibration stats are
    computed on demand from that pool, their rules/lessons are owner-scoped, and their calibration history is written
    as owner-scoped `calibration_runs`. Rates and categories are workspace reference data, editable by admins only.
49. **Cost locks**: model/provider/mode/budget come only from the environment; request bodies containing such keys are
    rejected with 400 (`model_locked`) and logged. Per-user daily cap (`USER_DAILY_USD_CAP`, admin-adjustable per
    user up to the global cap), per-user hourly limit on AI-triggering endpoints (in-process sliding window, so
    approximate across workers), max concurrent AI runs per user, global `LLM_BUDGET_USD`. Production refuses to
    start unless `LLM_MODE=live`, a 32+ char `SESSION_SECRET` and the OpenAI settings are present.
50. **Destructive operations removed**: `make reset` is disabled, the "reset learned data" endpoint is gone, and
    startup no longer replaces stored calibration with empty stats when the active model has no history (this
    happened once during this work when a server was started in fake mode against the dev DB; the stats were
    recomputed deterministically from the preserved records, see DATA_INVENTORY.md).
51. **Browser tests run on an isolated stack** (`frontend/e2e/run.sh`): a copy of the archive in `calibr_e2e`, fake
    LLM, a random admin password per run, separate Next build dir, so they never touch the dev data.
52. **Agent runs execute in a worker thread** behind the SSE response: heartbeats every 15 s while the model thinks,
    and a client disconnect never aborts a run (state is persisted; the panel resumes by polling `run_state`). The
    same run can be started without a stream (`/runs/async`), which the panel uses automatically when the stream
    cannot connect or shows no event within 20 s (`NEXT_PUBLIC_CHAT_TRANSPORT=poll` forces it).
53. **Selection context**: checked table rows are sent as `selected_task_ids` (validated to the estimate); the planner
    maps "these/selected" to them and the live model receives them as a note on the user message.
